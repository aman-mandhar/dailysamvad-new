Audit and Complete Open Graph Image Workflow for Social Media Sharing

Context

This Laravel news platform uses Filament for post management and serves public news articles on the frontend.

The goal is to verify and, where necessary, complete the full Open Graph image workflow so that every published post can be shared correctly on major social platforms.

The audit must cover:

Facebook

WhatsApp

LinkedIn

X / Twitter

Telegram

Other platforms that read Open Graph metadata

Do not assume the current implementation is correct. Inspect the actual project, identify gaps, implement safe fixes, test the output, and provide a completion report.

Primary Objective

Verify that each public post page generates a valid, publicly accessible and social-media-ready preview image.

The final implementation must ensure:

A post-specific Open Graph image is used when available.

A safe default site image is used when a post image is unavailable.

All metadata uses absolute HTTPS URLs.

The OG image URL is accessible without login.

The image is not blocked by authentication, storage permissions, robots rules, hotlink protection, Varnish, Nginx or Cloudflare.

Facebook, WhatsApp, LinkedIn, Telegram and X can fetch the image.

Existing WordPress-imported images and newly uploaded images both work.

Missing or invalid images do not produce broken social previews.

Security Requirements

Escape title, description and alt text.

Do not output arbitrary untrusted HTML inside meta attributes.

Validate external image URLs if remote images are supported.

Prevent javascript:, data: or unsafe schemes.

Allow only valid http or https public URLs.

Do not expose local server paths.

Do not expose private media.

Do not bypass authorization for draft article content.

Public image assets for published posts must remain publicly readable.

Performance Requirements

Do not run expensive image inspection repeatedly on every page request.

Reuse media metadata where available.

Cache computed metadata only if invalidation is correct.

Do not perform remote HTTP requests during normal article rendering.

Do not generate images inside the Blade request.

Avoid N+1 media queries.

Reuse eager-loaded featuredMedia where possible.
